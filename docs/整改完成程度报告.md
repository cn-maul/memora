**B2 每 chunk 事件广播 —— 🟡 基本完成（有边界风险）**
- 已做：`services.go:631-687` 用 30ms ticker + 32 字符缓冲聚合后 `emit`，`__STAGE__` 立即透出。
- ⚠️ 风险：`__STAGE__` 单独跳过缓冲，但 **`THINK`（思考块 `\x00MTHINK\x00`）没跳过**。思考块与内容块会进入同一个 `buf`；若在 30ms 窗口内或缓冲 <32 字符时二者混在一个 `emit` 里，前端 `qa.ts` 用 `chunk.startsWith(THINK_PREFIX)` 判断整块归属，会把思考文本与正文互相串染（正文漏进思考区 / 思考漏进正文）。
- **剩余方案**：在聚合循环里对 `strings.HasPrefix(chunk, contract.ThinkChunkPrefix)` 的块也**立即透出**（与 `__STAGE__` 同理），或 flush 前检测 `buf` 与前一个前缀是否一致、不一致先 flush 再写入。

**B3 idleReadCloser —— ⚠️ 有回归（需修正）**
- 现状：`stream_decode.go:102-131` 改成 `b.body.Read(p)` **同步阻塞**调用，随后才 `b.readCh <- struct{}{}`。问题是：定时器 `b.timer.C` 分支永远无法在 Read 阻塞期间触发 `b.body.Close()`——因为 Read 还没返回，代码根本走不到 `select`。结果是 **idle 断流超时保护失效**（对端停推但连接不关时，流式 goroutine 会永久悬挂）；且 `b.readCh` 每次 Read 仍 `make` 一次，「复用」名不副实。
- **剩余方案**（务必修）：恢复「goroutine 内 Read + select 定时器」的正确形态，或改用 `time.AfterFunc`：
  ```go
  func (b *idleReadCloser) Read(p []byte) (int, error) {
      type res struct{ n int; err error }
      ch := make(chan res, 1)
      go func() { n, err := b.body.Read(p); ch <- res{n, err} }()
      timer := time.NewTimer(b.idle)
      defer timer.Stop()
      select {
      case r := <-ch:
          return r.n, r.err
      case <-timer.C:
          b.body.Close()
          r := <-ch
          return 0, fmt.Errorf("[llm] 流式读取空闲超时")
      }
  }
  ```
  （即回到原实现；若坚持优化分配，用 `time.AfterFunc` 关闭 body 而非阻塞读返回。）
