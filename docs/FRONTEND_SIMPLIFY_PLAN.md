# Memora 前端「新手友好」简化改版计划书

> 版本：v1.1（审查修订版）
> 目标：让没有任何使用经验的小白，第一次打开软件、不读说明书、靠探索也能弄懂怎么用；界面元素更简洁，无用信息大幅减少。

## 0. 审查结论与修订重点

原方案对「术语过于专业、入口重复、设置复杂」的判断成立，但初稿存在五项风险：

1. **把三页合成三个 Tab 不等于简化**：用户仍要理解「文件 / 搜索 / 浏览」的边界，只是把一级导航搬成二级导航；
2. **系统状态不能全部隐藏**：自动保存、文档处理暂停或失败会影响用户信任，toast 关闭后不可追溯；应隐藏技术机制，但保留可理解、可恢复的状态；
3. **首次配置不能假设只需三个字段**：现有初始化同时依赖文档提取、聊天模型和嵌入模型，必须先自动检测，再按失败项渐进展示配置；
4. **“每页一个主按钮”过于机械**：版本记录和统计属于浏览页面，不应为了统一而强加主按钮；正确目标是每页只有一个清晰的主任务；
5. **直接删除页面风险过高**：应先复用现有组件形成统一工作流并保留深链接，验证后再清理旧实现。

本版采用更稳妥的方案：**三个主要目的地 + 一个统一文件工作台 + 渐进式系统状态 + 自动检测优先的首次配置**。

## 1. 现状问题诊断（为什么现在对小白不友好）

对现有前端逐页审查后，归纳出以下**五个核心问题**：

### P1 导航太多、层级混乱（7 个页面互相重叠）

左侧导航共 7 项：最近文件 / 全部文件 / 内容整理 / 版本历史 / 问答 / 统计 / 设置。

- 「最近文件」与「全部文件」功能高度重叠，小白分不清该点哪个；
- 「内容整理」实为搜索+标签+文件管理，命名太抽象；
- 「版本历史」页面标题写着"版本历史"，但左侧栏同区域又有一套"版本历史"（提交/保存按钮），同一概念出现两次；
- 一个功能（找文件/搜文件）分散在 3 个页面里，用户不知道去哪找。

### P2 术语太专业（Git/索引/向量是心理门槛）

页面上大量出现：HEAD、分支、commit hash、`索引状态`（pending/extracting/embedding/indexed/failed/ignored）、`重建索引`、`语义检索`、`向量`、`任务队列`、`AI 备注`、`MarkItDown`。

小白看到 `indexed / failed / ignored` 这种状态枚举，第一反应是"这是开发工具"，不敢乱点。

### P3 每个页面塞了太多功能块

- 左侧栏：菜单 + 版本状态 + 3 个统计数字 + 2 个保存按钮 + 「高级」折叠区（分支/HEAD/文件数）+ 底部设置/主题，一屏内容过载；
- 首页（RecentFilesPage）：时间窗切换 + 高亮过滤 + 文件列表 + 右侧对话面板同时出现；
- 内容整理页：语义搜索 + 标签墙 + 文件表格（6 列）+ 标签建议 + 重建索引按钮，挤在一起。

### P4 无引导、无空态说明，出错即白屏或一堆红色

- 未初始化工作区时只有一条横幅，没有"下一步该干什么"；
- 索引失败、模型未配置等状态，展示给用户的是 `failed`、`ai_unavailable` 这类码，没有"现在该做什么"的指引；
- 空态文案（如"还没有版本"）写了，但很多页面缺失。

### P5 布局是"技术工作台"而不是"日常工具"

左右可拖拽面板 + 主区，把应用做成了 IDE 布局。小白不需要调整面板宽度、不需要看到 HEAD 哈希、不需要"任务队列"概念。

## 2. 改版原则

| 原则 | 含义 |
|------|------|
| G1 一个页面一件事 | 每页只有一个核心任务，其余功能降级为次要入口或折叠 |
| G2 术语平民化 | 面向用户的所有文案改成大白话，技术术语只出现在"高级"区域 |
| G3 默认隐藏高级 | 参数、hash、队列、索引等一律默认折叠，需要时再展开 |
| G4 主任务明确 | 操作页突出一个主操作；浏览页突出信息层级，不强行放主按钮 |
| G5 空态即引导 | 没有数据时不是空白，而是"接下来该做什么"的指引 |
| G6 状态可见且可恢复 | 隐藏实现细节，但保存、处理中、失败、离线等关键状态必须可见并给出恢复动作 |
| G7 保守迁移 | 优先复用现有 API、Store 和页面组件，保留旧路由深链接，验证后再删除旧实现 |

## 3. 信息架构重构（导航从 7 项 → 3 个主要目的地）

### 3.1 新导航结构

| 新导航 | 对应旧路由 | 页面职责（一句话） | 小白理解 |
|--------|-----------|-------------------|----------|
| 文件 | `/files` | 最近文件、目录浏览、统一搜索 | "找和打开我的文件" |
| 问问题 | `/qa` | 对文档提问，AI 回答 | "有问题就问" |
| 版本记录 | `/timeline` | 每次保存的历史，可找回旧版 | "我的每一次改动" |
| 更多 | 弹出菜单 | 统计、设置、标签建议 | 低频功能集中入口 |

**具体动作：**
1. 将「最近文件」作为 `/files` 默认内容，顶部放一个统一搜索框；输入内容后在原位置展示文件名与内容搜索结果，不跳到另一个“搜索页”；
2. 目录树改成文件列表的视图切换（列表 / 文件夹），使用图标分段控制，不再设置「浏览」Tab；
3. 标签只作为搜索结果中的筛选条件，默认折叠为「筛选」，不再常驻标签墙；
4. 统计、设置、待确认标签属于低频任务，放入「更多」菜单；有待处理事项时仅在入口显示数字标记；
5. 第一阶段保留 `/workspace`、`/index`、`/stats`、`/settings` 的真实路由与深链接；从主导航隐藏，不立即重定向。完成可用性验证后，再决定是否重定向及删除旧页面。

> 这样做比“三个 Tab”更优：用户只需理解「文件」一个目的地，搜索是动作、列表/文件夹是视图，而不是三个需要选择的功能区。

## 5. 页面级简化方案

### 5.1 全局外壳（App.vue）

**现状问题：** 左侧栏信息过载 + 顶部队列横幅 + 右侧对话面板 + 可拖拽。

**改动：**
1. 左侧栏只保留：顶部 Logo/标题、3 个主要目的地、底部「更多」入口与主题切换。
2. 删除"版本历史"区块的三段式技术状态和分支/HEAD 信息，但保留一个可信赖的全局保存状态：`已自动保存` / `有改动，稍后自动保存` / `自动保存失败`。
   - 默认不显示手动保存主按钮，避免用户误以为必须手动操作；
   - 自动保存关闭或失败时才出现「立即保存」动作；
   - 点击保存状态可查看改动文件和「保存并写说明」，满足需要明确控制的用户；
   - 分支/HEAD/高级信息整体移除（G3），如需保留放「版本记录」页的「高级」折叠区。
3. 正常处理状态不占据页面；暂停、连续失败、离线等持续性问题使用可关闭但可再次找到的「系统状态」入口，附「继续处理 / 重试 / 去设置」动作。操作成功可用 toast，持续故障不能只用 toast。
4. 右侧对话面板：保留（这是核心卖点），但移到「问问题」页统一承载；「文件」页不再常驻右侧对话，避免一屏三栏。聊天内点击文件链接仍可跳回文件页。
5. 主题切换按钮保留，放在「更多」入口旁边；设置从「更多」菜单进入。

**简化后布局：**
```
┌──────┬──────────────────────────────┐
│ 菜单 │                              │
│ 文件   │         主内容区           │
│ 问问题 │   （每页只有一个主任务）      │
│ 版本记录 │                            │
│──────│                              │
│ 🌙 更多 │                              │
└──────┴──────────────────────────────┘
```

### 5.2 文件页（统一工作台）

**默认状态：** 最近打开或修改的文件 + 顶部统一搜索框 + 列表/文件夹视图切换。

- 搜索框占据页面最明显位置，提示词为「搜索文件名或文档内容」；输入后混合返回文件名匹配与内容匹配，结果中用「文件名匹配 / 内容匹配」说明原因；
- 默认最近 7 天；时间范围放入「筛选」菜单，保留能力但不让用户首次进入就做决定；
- 搜索结果只展示文件名、所在文件夹、匹配片段和标签；匹配度默认不显示百分比，排序已经表达相关性，只有高级详情可查看分数；
- 文件状态仅在异常或用户打开详情时显示；正常文件不重复显示「可搜索」标签；
- 「重新整理全部文件」移到设置的诊断区；单文件失败时直接在该行显示「重新处理」。

**不删除但降级：** 状态筛选、标签管理、标签建议、批量重建。它们进入筛选菜单、更多菜单或设置诊断区，避免出现问题后无处恢复。

### 5.3 问问题页（QAPage）

**现状基本合理，微调：**
1. 模式切换「全局/文件问答」改为更直白的选项：默认**全局**（"问我的所有文档"），文件问答做成"在某个文件里问"的次级入口（选中具体文件时自动切换）；
2. 去掉"会话列表"左侧栏的抽象感：保留但改名为「历史对话」，空态写"和文档聊过的话会存在这里"；
3. 空态引导文案增强：首条消息区显示 3 个示例问题按钮（如"我最近在忙什么？"），点击即提问，引导小白迈出第一步。

### 5.4 版本记录页（TimelinePage）

**现状：** 展示的是"提交列表 + 文件明细"，概念偏专业。

**改动：**
1. 顶部副标题改为大白话："每次自动保存都会形成一个记录，改动错误可以在这里找回旧内容"；
2. 每条记录的显示：`时间 + 一句话说明 + 改动了几个文件`；AI 摘要不可用时回退到保存说明，不让页面依赖模型能力；折叠后才是文件明细 + 高级（hash、作者）；
3. 「保存当前改动」的能力已在文件页，本页只做"查看与找回"；
4. 保留"恢复此版本"动作；工作区有未保存改动时，不能承诺后端未实现的自动处理，明确给出「先保存当前改动并继续」和「取消」两项，保存成功后再执行恢复。

### 5.5 统计页（StatsPage）

**现状已较清爽，微调：**
1. 「导出」合并成右上角菜单，不直接删除；需要提交周报的办公用户仍可能依赖它；
2. 卡片文案平民化："活跃度 12.3%（你整理和更新文件的频率）" 这类已不错，保留；
3. 无数据空态已有引导，保留。

### 5.6 设置页（SettingsPage，最大改动）

**现状 1580 行，是重灾区。** 拆分两层：

- **简化层（默认展示，小白只看到这里）**：
  - 工作区：选择文件夹（主按钮"选择我的工作文件夹"）；
  - AI 服务：优先选择服务商预设，再填写密钥；同一服务商的地址和推荐模型自动带入；
  - 默认将同一服务地址和密钥复用于回答模型与文档整理模型，只在检测到不兼容或用户展开高级设置时分别配置；
  - 其余所有参数（temperature、dimensions、chunkSize、自动保存间隔、Python 路径、MarkItDown 命令、托盘、统计开关）全部收进"高级设置"折叠区；
- **高级层（折叠）**：原全部字段分组保留；另增「诊断与修复」，集中提供重新处理、连接测试和可复制的错误详情。

## 6. 首次使用引导（一次性向导）

目标：小白第一次打开就知道"三件事"。

1. **选择文件夹**：大按钮 + 最近选择，先只读取可处理文件数量，不启动模型处理；明确说明不会移动原文件；
2. **自动检查**：后台检测文档提取工具；成功则自动通过，失败才展开 Python/文档提取工具配置，不让所有用户都面对专业字段；
3. **连接 AI 服务**：先选服务商预设并填密钥，自动测试回答和文档整理两项能力；只有其中一项失败时才要求分别设置模型；
4. **开始准备**：提交现有 `/api/workspace/init`，进入文件页并在不遮挡操作的状态区显示真实进度；可先浏览文件，搜索/问答在准备完成后逐步可用；
5. **首次成功时引导行动**：准备好后在搜索框下给出「搜索一份文件」和「向文档提问」两个上下文入口，不增加整屏完成页。

要点：不是绝对隐藏 Python/MarkItDown，而是**自动检测成功时不展示，失败时就地解释并提供修复**。现有 `/api/workspace/init` 同时需要提取与嵌入配置，向导必须忠实反映这个事实。

### 6.1 全局状态模型

所有页面按统一状态响应，避免每页各写一套提示：

| 状态 | 用户看到什么 | 可执行动作 |
|------|--------------|------------|
| 未初始化 | 选择文件夹与连接 AI 服务 | 开始设置 |
| 准备中 | `正在准备 12/80`，已扫描文件仍可浏览 | 后台继续 |
| 可用 | 默认不显示技术状态，仅显示最近文件 | 搜索、打开、提问 |
| 部分可用 | 如「文件可以浏览，内容搜索暂不可用」 | 重试 / 去设置 |
| 已暂停 | 「文档处理已暂停」 | 继续处理 |
| 离线或服务失败 | 保留本地文件浏览与版本记录 | 重新连接 / 去设置 |

## 7. 空态与错误提示规范（统一原则）

- **空态 = 引导**：任何列表无数据时，显示"这里会显示……" + 一个可点击的主操作按钮；
- **错误提示 = 下一步**：`failed` 状态不显示红色英文码，而是"这个文件处理失败了，点这里重试"；`ai_unavailable` 改为"模型没连上，去设置里检查一下"并附「去设置」按钮；
- **反馈分级**：操作成功用 toast；需要用户处理的持续问题用页内状态或全局状态入口；危险操作用对话框；
- **错误分两层**：先显示可理解的摘要与恢复动作，提供「查看详情」展开后端 message，便于排障但不直接用错误码吓用户；
- **文案集中化**：当前 `zh.ts` 尚未接入，实施时应建立错误码到展示文案的映射 helper；无需为了本次改版先引入完整国际化框架。

| 阶段 | 内容 | 涉及文件 | 验收 |

## 9. 明确不做的事（防止范围膨胀）

- 首轮不改后端接口；若统一搜索或服务商预设无法在前端可靠编排，登记为明确依赖后再评估，不伪造能力；
- 不做多语言（界面仅中文，维持现状 D26）；
- 不重做设计系统/动效（现有 style.css 设计令牌够用）；
- 不新增"教程弹窗"反复打扰：一次性引导 + 空态引导足够，不做强制新手教程；
- 不动文件系统结构（工作区/.memora 逻辑与前端无关）。

## 10. 验收标准（对照第 1 章五个问题）

- [ ] P1：主导航为 3 个目的地 + 更多；用户无需理解“最近/全部/内容整理”的边界；
- [ ] P2：全站面向用户的文案无技术黑话；
- [ ] P3：每个页面首屏只呈现一个主任务，其余折叠/隐藏；
- [ ] P4：所有空态与错误状态都有"下一步该做什么"；
- [ ] P5：布局去掉 IDE 式三栏与可拖拽面板，持续性系统状态仍然可见、可恢复。

体验验收（至少 5 名没用过 Memora 的用户，任务顺序随机）：
1. 80% 用户能在 3 分钟内完成「选文件夹 → 连服务 → 开始准备」，且不需要口头指导；
2. 90% 用户首次点击就能进入文件、问答、版本记录三个核心目的地；
3. 80% 用户能在 60 秒内找到并打开指定文件；
4. 80% 用户能独立提出一个问题，并理解回答来自哪些文件；
5. 80% 用户能找到旧版本，理解恢复影响并在确认前停下；
6. 窄窗口（1024px 宽）无重叠或水平滚动；所有核心操作可用键盘完成，焦点可见；
7. 失败场景测试覆盖：AI 服务不可用、文档提取失败、处理暂停、工作区有未保存改动。
